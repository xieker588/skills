# 方案总成：本地动漫桌面 AI 搭子

> 工程纪律：本方案以 **harness engineering（编排/控制层工程）** 与 **loop engineering（核心循环工程）** 为两根支柱组织。前者定义"谁来驱动、怎么编排、如何保证安全与可恢复"；后者定义"每一次交互如何稳定、低延迟、可打断地转起来"。

## 0. 目标与边界

- **定位**：自己用的本地二次元桌面 AI 搭子，不是产品。
- **必备能力**：语音唤醒 · 自然对话(可打断) · 动漫形象(Live2D/VRM) · 操控电脑 · 跨会话长期记忆。
- **硬约束**：核心链路本地优先、隐私第一；危险动作不自动执行；可中断、可恢复。
- **非目标**：不做云端 SaaS、不做多租户、不做商业分发。

## 0.5 基座决策：自建优先（用户指令「自建」）

> 自检结论 B1：原"以 Project AIRI 为底座"与「遵守 harness/loop engineering」及「用户最在意记忆+操控」三处自相矛盾。现据用户「自建」指令定调：

- **自研 Harness + Loop 引擎为唯一真值**：我们拥有编排核心、状态机、权限闸门、自检与恢复逻辑。这是本方案的两根工程纪律的落点，不能外包给现成 App。
- **AIRI / Open-LLM-VTuber 降级为「参考模块」（borrow，不 base）**：
  - AIRI → 借其 Live2D/VRM **渲染范式**与桌宠窗口集成思路，不自用其 UI；桌宠 UI 由我们自绘（§4）；
  - Open-LLM-VTuber → 借其 **Letta 记忆**与 **MCP 操控**的实现范式（这是记忆+操控两段最强参考）；
  - 二者均以"可替换子模块"形式接入我们的 Orchestrator，接口对齐即换，不绑定。
- **好处**：记忆与操控（用户第一诉求）完全自主可控；harness/loop 纪律真正落地；未来可整包替换任意子模块而不动主架构。

## 1. 总体架构（分层）

```
┌─────────────────────────────────────────────────────────┐
│  形象层 Avatar    Live2D/VRM 透明桌宠 UI（置顶/穿透/拖拽） │
├─────────────────────────────────────────────────────────┤
│  表达层 Expression   TTS → 口型同步 → 情绪/表情映射        │
├─────────────────────────────────────────────────────────┤
│  认知层 Cognition     LLM + Planner + 记忆层(Letta/Mem0)   │
├─────────────────────────────────────────────────────────┤
│  执行层 Action       MCP Tool Server（开应用/文件/读屏/命令）│
├─────────────────────────────────────────────────────────┤
│  感知层 Perception    Mic→VAD→STT；屏幕捕获；摄像头(可选)   │
├─────────────────────────────────────────────────────────┤
│  运行时 Harness      Orchestrator/ServiceContext + 状态机  │
│                   + 权限沙箱 + 持久化 + 可观测性           │
└─────────────────────────────────────────────────────────┘
```

各层通过接口解耦，LLM/ASR/TTS/Memory 均可本地 ↔ API 热切换。

### 1.5 本地资源预算（消费级硬件约束，自检 M5）

同机同时跑"本地 LLM + Live2D 渲染 + STT + TTS"会抢显存/内存，须先建模再定档：

| 档位 | GPU 显存 | 内存 | LLM 选择 | 说明 |
| --- | --- | --- | --- | --- |
| 最低 | 6 GB | 16 GB | Ollama qwen2.5:3b/7b（Q4） | 仅能打字或短时语音；Live2D 简易模型 |
| 用户(实测) | 10 GB | 16 GB | qwen2.5:7b（Q4，~4.5GB） | 打游戏+行政；留 ≥5GB 给游戏/渲染，**禁 14B** |
| 推荐 | 12–16 GB | 32 GB | qwen2.5:14b（Q4/Q5） | 语音+形象+记忆可同跑（≥12GB 适用） |
| 充裕 | 24 GB+ | 64 GB | 32b/更大 或 多模态 | 全功能常开 |

- **进程优先级**：STT/VAD（实时性最高）> TTS > Avatar 渲染 > LLM 推理；LLM 推理可让出显存峰值。
- **显存分配上限**：LLM 服务设 `gpu_layers`/显存上限，预留 ≥2 GB 给渲染与音频。
- **争用兜底**：显存不足时 LLM 自动回落 API（§2.2 降级），其余链路保持本地，不整体降级隐私。
- **游戏争用模式（用户场景：常打游戏）**：Harness 监听前台 GPU 进程；检测到 3D 游戏占用超阈值时，本地 LLM 自动让出显存——暂停本地推理并回落到用户自有 DeepSeek-V4-Pro API（0 积分，仅作临时、牺牲部分隐私），语音/形象降为轻量运行；游戏退出后自动恢复本地 7B。避免桌宠与游戏抢 GPU 导致卡顿。详见 `references/local-llm-options.md` 第五节。

### 1.6 隐私数据流（硬约束：本地优先，§0 隐私第一）

本地链路（默认，数据不出本机）：
```
mic → 本地STT → 本地LLM(Qwen2.5-7B) → 本地TTS → 扬声器
记忆/配置/审计 → 本地 SQLite + Markdown
```
外发链路（仅显式回落，牺牲部分隐私）：
```
打游戏/显存不足 → LLM 请求 → DeepSeek-V4-Pro API（用户自有 Key）
```
⚠ 仅 LLM 文本对外；**音频/记忆/屏幕永不外发**。回落期间不写长期记忆到云端。
红线：唤醒词音频、记忆库、屏幕截图 永不进任何外部服务。

## 2. Harness Engineering（编排/控制层）

Harness = 真正"跑起来"的运行时。它不负责聪明，只负责**可靠地把聪明串起来**。

### 2.1 单一编排核心（Orchestrator / ServiceContext）
- 装载并持有 ASR、VAD、LLM、TTS、Memory、MCP、Avatar 七个实例；
- 切换角色/配置时按"基础配置 ⊕ 角色配置"合并后热重载，不重启进程；
- 所有跨层调用经它中转，便于统一加权限闸门与日志。

### 2.2 模块可插拔 + 降级
- LLM/ASR/TTS/Memory 各自定义接口，本地与 API 实现可换；
- 降级策略：TTS 失败回落 Edge TTS；本地 LLM 过载回落小模型/API；STT 噪声大启用 FunASR。

### 2.3 状态与持久化（可恢复）
- 会话状态、记忆、配置落本地（SQLite + Markdown）；
- 崩溃重启后从最近检查点恢复，不丢记忆、不重复执行；
- 每条"指令 → 动作 → 结果"写审计日志（本地）。
- **检查点与幂等（自检 M3）**：每个动作带唯一 `action_id` 与状态机 `queued → dispatched → acked → done`。
  - 进程在 `dispatched` 未 `acked` 时被杀：重启后**不自动重放**，进入"待人工裁决"队列，由用户确认是否补执行——避免幂等失败导致二次执行（如重复重命名/重复跑脚本）。
  - `done` 动作写入不可变审计，供 §2.7 自检回放。

### 2.4 权限/沙箱模型（安全围栏，操控电脑的命门）
动作分级：
- **L0 只读**（读屏/读文件/查状态）——自动
- **L1 写**（建/改文件、开应用）——确认或沙箱
- **L2 执行**（运行命令、装软件）——显式确认 + 可撤销
- **L3 外部通信**（发消息/转账/联网发布）——永远人工确认，AI 不主动发起
- 沙箱：文件操作限工作目录(cwd)；命令限白名单；所有 L2/L3 入审计。

#### 2.4.1 语音确认协议（自检 M2，纯语音场景关键）
整条链路为语音对话，用户常不碰键盘，故 L2/L3 确认不能用"点按钮"：
- **L2 确认**：AI 复述动作 + 等你说出唤醒词/确认词（如"执行"）才放行；超时或说"取消"即中止。
- **L3 确认**：除复述+确认词外，要求**二次独立唤醒词**（防误唤醒触发外发）；默认拒绝，AI 绝不在未获明确二次确认时发起。
- **零信任兜底**：命令含 `rm -rf`/格式化/转账/群发等破坏性语义时，无论分级一律升级为 L3 双确认，且执行前再朗读目标路径/金额一次。
- **可撤销边界（明确）**：L2 执行后保留 `undo` 指令窗口（如 60s），说出"撤销"触发回滚。**仅文件类操作能真正撤销**——移动/改名走系统回收站、非硬删，可逆；**运行命令类 L2 是 best-effort**（如已启动进程可 kill、已装软件可卸载，但命令副作用不保证可还原）。破坏性命令（rm -rf/格式化）不提供 undo，只能事前双确认拦截。

### 2.5 配置即代码
- `conf.yaml` 驱动全局；角色 persona 独立 YAML；改配置即改行为，可版本化。
- **最小骨架**（P0 起即用，详见 `deploy.md`）：
  ```yaml
  persona: conf/persona.yaml          # 角色人设（见 persona-template.md）
  llm:
    provider: ollama
    model: qwen2.5:7b                 # 用户 10GB 卡；12GB+ 可升 14b
    gpu_layers: 32                    # 显存上限，预留给渲染/游戏
    fallback:                         # 争用兜底（§1.5）
      when: gpu_busy_or_api           # 打游戏/显存不足时
      provider: deepseek              # 用户自有 Key，0 积分
      model: DeepSeek-V4-Pro
  stt:  { provider: sherpa-onnx, model: paraformer-zh }
  tts:  { provider: edge-tts, voice: zh-CN-XiaoyiNeural }
  vad:  { provider: silero, threshold: 0.5 }
  memory: { engine: letta, path: ./data/memory }
  mcp:
    cwd: ./workspace                  # 文件操作沙箱根
    command_whitelist: [explorer, notepad]
  permissions:
    level: L1                         # 默认等级，危险动作升级
    voice_confirm: true              # 纯语音场景启用 §2.4.1 协议
  ```

### 2.6 可观测性
- 日志、token 消耗、端到端延迟打点；音频/推理/渲染分线程，带背压。

### 2.7 自检子系统（Self-Check Loop，用户指令「自检」）
Harness 内常驻一个**轻量自检循环**，独立于对话循环，主动发现"带病运行"并校正，而非等用户投诉。

五类自检：
1. **模块存活**：ASR/VAD/LLM/TTS/Memory/MCP/Avatar 七实例心跳；挂掉按 §2.2 降级或重启子进程，不拖垮主循环。
2. **记忆完整性**：记忆库条目缺 `来源/时间戳`、摘要断裂、磁盘损坏 → 标记隔离，不注入 prompt；定期归档压缩（§8）。
3. **配置漂移**：当前运行配置与 `conf.yaml` / persona 比对；漂移超阈值告警并回滚到最近一致版本。
4. **动作审计回放**：重放 §2.3 不可变审计，核对 `dispatched` 是否都有 `done`；孤儿动作挂"待裁决"（关联 M3）。
5. **延迟/资源契约**：实测 TTFT/端到端是否破 §3.2 预算、显存是否破 §1.5 上限；破约触发降级（LLM→API）或降画质。

- **触发时机**：启动时全量自检；运行中每 N 分钟（默认 5）抽样；每个空闲循环（§3.3）搭话前先过一遍；危险动作执行前过一遍（零信任）。
- **校正动作**：降级 / 重启子模块 / 隔离坏记忆 / 回滚配置 / 挂待裁决 / 报告用户（口头+日志）。
- **不自杀**：自检失败本身绝不终止主进程；最坏仅缩小能力面（如关语音留打字），保"活着"。

## 3. Loop Engineering（核心循环）

两条循环：**常开感知循环**（低功耗）与 **对话-行动循环**（ReAct）。

### 3.1 常开感知循环（Listen Loop）
```
mic ─▶ VAD ─▶ 唤醒词检测 ─(命中)─▶ 触发对话循环
          └────────(未命中)────────▶ 继续监听（空闲动画）
```
- 常开但低耗：本地 STT 仅对唤醒词片段；命中才拉起全量对话循环。

### 3.2 对话-行动循环（Dialogue-Action Loop）
```
  ┌──────────────────────────────────────────────┐
  │ 1. Capture    音频流 / 文本                    │
  │ 2. Transcribe STT → text（含 barge-in 检测）  │
  │ 3. Recall      记忆层检索(指令/状态/偏好)注入   │
│ 4. Reason      LLM + 规划 → 是否需要工具        │
│ 5. Act        ├─ 不需工具 → 直接回复           │
│               └─ 需工具 → ⚡零信任自检(§2.7) →【权限闸门】(§2.4) → MCP │
  │ 6. Observe     工具结果/屏幕状态回灌            │
  │ 7. Express     流式 TTS + 情绪映射 → Avatar      │
  │ 8. Persist     (指令+结果+状态) 写记忆层        │
  │ 9. ──────────────┐ 回到 1（支持随时打断）      │
  └──────────────────┘                            │
  barge-in：任何时刻检测到用户语音 → 立即打断 TTS/动作 │
  └──────────────────────────────────────────────┘
```
- **barge-in（可打断）**：VAD 检测用户插话即停 TTS/挂起动作，体验接近真人。
- **反馈闭环**：第 5→6 步每次工具调用都是 mini feedback loop；失败触发重试/降级/自我校正，再回到 4。
- **延迟预算（自检 M4，量化）**：

| 阶段 | 本地档（推荐配置） | 降级档（LLM→API/小模型） |
| --- | --- | --- |
| VAD 唤醒判定 | < 50 ms | 同 |
| STT 首字（用户停句→出字） | < 400 ms | < 600 ms |
| LLM TTFT（首 token） | < 800 ms（7b Q4，用户实际） | < 1200 ms |
| TTS 首字节（边生成边播） | < 200 ms | < 400 ms |
| 端到端 p95（唤醒→出声） | < 1.6 s | < 2.4 s |

- TTS 流式边生成边播；工具调用并行预取；避免"等说完才能动"。破约由 §2.7 自检触发降级。

### 3.3 空闲循环
- 无操作 N 分钟 → 先过 §2.7 自检（避免带病卖萌）→ routine 触发主动搭话/随机动画，维持"活着"的感觉。

## 5. 记忆模型（用户最在意）

- **三类记忆**：指令记忆（你下过什么）、状态记忆（项目/电脑当前进度）、偏好记忆（人设/禁忌）。
- **双层**：短期 = 会话上下文窗口；长期 = Letta/Mem0 本地持久。
- **写入**：每轮对话后结构化摘要落盘；重要/危险操作必写。
- **召回**：相关检索注入 system prompt；跨 session 续聊。
- **隐私**：全本地，不外发。

### 5.1 记忆一致性（自检 M6）
- **条目元数据**：每条记忆带 `timestamp + source + confidence`；volatile 状态（如"正在跑 X"）与持久记忆分离存储，状态结束即归档或失效。
- **冲突消解**：多 session 上报矛盾的项目状态时，以**最新且带证据者**为先；低置信/矛盾项挂"待确认"队列，口头问你确认，**不自动采纳**覆盖。
- **去重**：写入前按语义相似度去重；同义指令合并、过期条目标记失效而非物理删（保留审计）。
- **真值来源**：记忆是"你对搭子说过什么的记录"，不是"电脑客观状态的真值"；执行类状态以工具回灌（§3.2 第 6 步 Observe）为准，记忆仅作提示。

### 5.2 用户真实行政任务 → 能力映射（本项目实际用途）

桌宠只干行政杂活，不替代创作/游戏。映射到记忆 + 工具：

| 你的活儿 | 需要的模块 | 权限等级 | 记忆落点 |
| --- | --- | --- | --- |
| 整理 / 归类文件 | MCP 文件工具 + 记忆 | L1（沙箱 cwd） | 状态记忆：整理规则 / 位置 |
| 搜索资料 / 网页 | MCP 搜索工具 | L0 / L1 | 指令记忆：常搜主题 |
| 查投稿 / 投递记录 | MCP 读文件 / 表格 + 浏览器 | L0 / L1 | 状态记忆：各平台进度 |
| 提醒待办 | 记忆 + 定时 routine | L0 | 偏好 / 状态记忆 |

## 6. 安全围栏（操控电脑的必须）

见 2.4 动作分级 + 沙箱 + 审计。红线：**AI 绝不主动发起外部通信**；L2/L3 永远人确认。

## 7. 分阶段路线（MVP → 完整）

- **P0 骨架+形象+对话**：搭自研 Harness 最小骨架（Orchestrator+状态机+配置），先借 AIRI/OLVT 的 Live2D/VRM 渲染出形象，能打字聊、有情绪。**此阶段即验证"我们拥有编排"而非套壳**。
- **P1 语音**：接 STT+TTS+barge-in，能说能打断。
- **P2 记忆**：接 Letta，跨 session 记得你干过啥。
- **P3 操控**：先只读/安全写（开应用、整理文件），过权限闸门。
- **P4 常开**：唤醒词 + 桌宠常驻（透明/置顶/穿透）。
- **P5 强化**：主动搭话 + 安全围栏打磨 + 性能调优。

## 8. 风险与缓解

| 风险 | 缓解 |
